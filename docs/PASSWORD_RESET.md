# AUTH-003 비밀번호 재설정

가입된 교사가 이메일로 본인 확인 후 비밀번호를 재설정합니다. 학생은 비회원 PIN 참여 방식이므로 계정 복구 대상이 아닙니다. 기존 로그인 상태의 비밀번호 변경 API와 별개입니다.

## 1. 재설정 링크 요청

`POST /api/auth/password-reset/request` (로그인 불필요)

```json
{"email":"teacher@example.com"}
```

202 응답:

```json
{"message":"가입된 이메일이면 비밀번호 재설정 안내를 발송했습니다. 메일함을 확인해주세요."}
```

- 이메일은 소문자·앞뒤 공백 제거로 정규화합니다. 형식 오류는400입니다.
- 활성 교사 계정에만 메일을 보냅니다. 미가입·비활성·학생 계정 및60초 안의 재요청도 동일한202 본문을 반환하며 토큰·가입 여부·만료 시각을 반환하지 않습니다. 재요청 제한 중에는 다시 발송하지 않습니다.
- 256비트 난수(URL-safe Base64 43자) 토큰은15분 유효하며 DB에는 SHA-256 해시만 저장합니다.
- 재발급 성공 시 과거 미사용 링크는 무효화합니다. SMTP 실패 시 새 토큰 생성과 과거 링크 무효화가 함께 롤백됩니다.
- 이미 사용한 링크는 재발급 후에도 사용 완료 오류로 구분합니다.

## 2. 메일 링크와 프런트 연동

기존 SMTP 설정과 발신 주소를 재사용하며 아래 환경변수를 추가합니다.

```dotenv
LIT_PASSWORD_RESET_URL=https://3.25.143.224/reset-password
```

실제 프런트의 재설정 페이지 URL로 설정하세요. HTTPS 절대 URL만 받으며 사용자 정보·query·fragment를 포함하면503입니다. 설정 변경 후 서버 재시작이 필요합니다. 설정되지 않으면 가입 여부와 관계없이503 `PASSWORD_RESET_NOT_CONFIGURED`입니다.

메일 링크: `https://YOUR_FRONTEND_DOMAIN/reset-password#token=43자리토큰`

프런트 페이지 구현은 별도입니다. URL fragment는 페이지 요청에 포함되지 않습니다. 프런트는 다음 순서로 연동합니다.

1. `location.hash`의 token을 메모리에 읽은 뒤 `history.replaceState`로 주소에서 제거합니다. 로그·분석 도구·영구 저장소에 토큰을 남기지 않습니다.
2. 새 비밀번호와 비밀번호 확인 입력을 받고 일치 여부를 검사합니다. 서버에는 아래 JSON을 전송합니다. 기존 Authorization 헤더를 첨부할 필요가 없습니다.
3. 링크를 여는 것만으로 토큰을 소비하지 않습니다. 프런트는 실패 코드를 표시하고, 만료·무효·사용 완료이면 재발급 화면으로 안내합니다.
4. 성공 시 저장된 로그인 토큰을 삭제하고 로그인 화면으로 이동합니다. 자동 로그인 응답은 제공하지 않습니다.

## 3. 새 비밀번호 확정

`POST /api/auth/password-reset/confirm` (로그인 불필요)

```json
{"token":"43자리토큰","newPassword":"New-password-456"}
```

200 응답:

```json
{"message":"비밀번호가 변경되었습니다. 새 비밀번호로 다시 로그인해주세요."}
```

- 재설정 비밀번호는 10~128자이며 공백만 입력할 수 없습니다. 현재 비밀번호와 같으면 400 `PASSWORD_UNCHANGED`이며 링크는 소비하지 않습니다.
- 성공 시 PBKDF2 비밀번호 저장, 로그인 실패 횟수·일시 잠금 해제, 모든 기기 access/refresh 세션 폐기, 토큰 소비 및 다른 링크 무효화를 하나의 DB 트랜잭션으로 처리합니다. 새 비밀번호로 다시 로그인합니다.
- 요청 당시 비밀번호 해시와 이메일을 결합한 지문도 저장합니다. 로그인 후 비밀번호 또는 이메일 변경으로 자격 증명이 바뀌면 이전 재설정 링크는 무효입니다.
- 계정 → 토큰/세션 순으로 잠가 로그인·갱신과 동시 실행을 직렬화합니다. 같은 링크의 동시 확정은 하나만 성공합니다.
- 가입 이메일 인증 토큰은 별도 테이블이며 재설정 토큰으로 사용할 수 없습니다. 토큰 원문·비밀번호는 API 응답 및 애플리케이션 로그에 출력하지 않습니다.

## 오류

| HTTP | code | 의미 |
|---|---|---|
| 400 | INVALID_REQUEST | 이메일·토큰 형식 또는 비밀번호 규칙 오류 |
| 400 | PASSWORD_RESET_INVALID | 알 수 없는 토큰, 재발급 또는 비밀번호 변경으로 무효화, 비활성 계정 |
| 400 | PASSWORD_RESET_EXPIRED |15분 유효 기간 만료 |
| 400 | PASSWORD_RESET_USED | 이미 사용된 링크 |
| 400 | PASSWORD_UNCHANGED | 현재 비밀번호와 같음 |
| 429 | RATE_LIMITED | IP당 각 경로30회/분 초과 |
| 502 | EMAIL_DELIVERY_FAILED | SMTP 전송 실패(내부 오류·인증 정보는 노출하지 않음) |
| 503 | PASSWORD_RESET_NOT_CONFIGURED | SMTP·발신 주소 또는 프런트 URL 설정 누락/오류 |

IP 제한은 기존 단일 서버 메모리 방식입니다. SMTP 공급자 오류로 발송 실패한 요청은502이므로 프런트에서 재시도를 안내합니다. 성공 응답은 실제 수신함 도착을 보장하지 않습니다. 운영 실메일 검증에는 실제 프런트 URL·SMTP 설정 및 수신함 확인이 필요합니다.

## DB 호환성

`schema.sql`은 기존 데이터를 바꾸지 않고 `password_reset_tokens` 테이블과 인덱스를 추가합니다. 회원 탈퇴의 계정 익명화 전에 토큰 행도 명시적으로 삭제합니다. 계정 행의 물리 삭제 시에는 FK `ON DELETE CASCADE`로 함께 삭제됩니다. 만료·소비·무효화 이력을 남기며 현재 별도 정리 작업은 없습니다.


운영 GitHub 배포는 URL 설정이 없거나 비어 있을 때 PRODUCTION_URL origin + `/reset-password`로 초기화합니다. 명시한 URL·SMTP 비밀값은 변경하지 않습니다. 수동 배포에서는 위 환경변수를 직접 설정하세요.
