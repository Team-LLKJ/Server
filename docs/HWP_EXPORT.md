# AI 활용 리포트 HWP 내보내기

기존 AI 활용 리포트의 특정 저장 버전에서 학생 답안·분석·교사 검토를 실제 HWP 5 바이너리 문서로 생성합니다. JSON·HTML 파일의 확장자만 바꾸거나 HWPX로 대체하지 않습니다. 기존 PDF API와 저장 데이터는 유지합니다.

## API

| 대상 | 메서드 | 경로 | 인증 |
|---|---|---|---|
| 담당 교사 | GET | `/api/teacher/evaluations/{id}/students/{participantId}/report/hwp` | `Authorization: Bearer ...` |
| 해당 학생 | GET | `/api/evaluations/{id}/report/hwp` | `X-Participant-Token: ...` |

각 `/report/hwp` 경로 대신 `/report.hwp`도 지원합니다.

쿼리:

- `version`: 저장된 리포트 버전,1 이상 정수. 생략 시 최신 저장 버전입니다.
- `includeConversations`: 기본 `false`. `true`일 때만 AI 질문·응답 원문과 질문 원문 기반 분류 근거를 포함합니다. 기본 응답에는 분류 결과·도구/모델·반영 이력과 제출 답안만 포함하며 대화 원문은 제외합니다.

200 응답:

```http
Content-Type: application/x-hwp
Content-Disposition: attachment; filename="lit-report-{reportId}-v{version}.hwp"
Cache-Control: no-store
```

응답 본문은 HWP 바이너리입니다. 프런트는 JSON이 아닌 Blob/ArrayBuffer로 받아 첨부 다운로드하며, 필요하면 인증 헤더를 넣어 fetch합니다. `Content-Disposition`은 기존 CORS 설정에서 노출됩니다.

## 리포트 준비·버전

1. 학생이 답안을 최종 제출합니다(자동 제출도 포함).
2. 기존 `POST /api/evaluations/{id}/reports` 또는 교사용 `POST /api/teacher/evaluations/{id}/students/{participantId}/reports`로 리포트를 생성합니다. 기존 백그라운드 생성 결과도 사용할 수 있습니다.
3. HWP GET을 호출합니다. GET은 새 리포트·분석·버전을 만들지 않습니다. 생성된 리포트가 없으면404입니다.
4. 교사 검토를 갱신한 경우 새 리포트를 생성한 뒤 해당 버전을 다운로드합니다.

버전을 지정하면 당시 저장된 제출 스냅샷·분석·교사 검토를 사용합니다. 이후 답안 라이브 데이터나 교사 검토가 바뀌어도 기존 버전의 다운로드 내용은 유지됩니다. 이 API는 기존 리포트 모델을 변환하며, 별도 100점 채점 API의 결과를 기존 리포트에 새로 합치지는 않습니다.

## 포함 내용·서식 범위

- 평가명, 학생 닉네임, 제출·생성 시각, 리포트 ID·버전·제출 해시
- 분석 방식·상태·기록 부족 사유·판단 한계·AI 허용 정책
- 기존5개 영역 교사 점수·배점·근거·합계/부분합·의견·검토자·검토 시각(미검토 상태 구분)
- 문항별 문제·최종 제출 답안(빈 답안 표시 포함)
- AI 활용 목적·단계 분류, 도구·모델·응답 상태, 직접 작성·참고·수정 이력
- 선택한 경우에만 AI 대화 원문

보고서 서식을 갖춘 편집 가능한 HWP 문서입니다. 중앙 정렬의 23pt 제목·14pt 평가명, 학생 정보 2열 표, 번호가 있는 파란색 섹션 제목, 5개 영역 점수 요약 3열 표, 문항별 제목·최종 답안, 검토 근거·교사 의견을 구분합니다. 표는 문자열 구분자가 아닌 실제 HWP 표이며 테두리·머리글 배경·반복 머리글을 적용합니다. 긴 답안과 근거는 고정 높이 표 안에 넣지 않고 일반 문단으로 이어서 페이지를 나눌 수 있게 합니다. 시각은 읽기 쉬운 한국 표준시(KST)로 표시합니다. 미입력 점수는0으로 바꾸지 않습니다.

보고서의 정보·점수 요약 표와 별도로, **학생 답안 내부의** HTML 문단과 줄바꿈은 변환하고, HTML 표는 행별 `셀1 | 셀2` 텍스트로, 이미지는 `[이미지]`로 표시합니다. 에디터의 색상·굵기·표 병합·이미지·복잡한 배치를 그대로 복원하는 HTML 변환기는 아닙니다. 긴 본문은 문단을 나누고 줄·페이지 배치는 문서를 여는 한글 프로그램이 다시 계산합니다. 글꼴·프로그램 버전에 따라 배치가 달라질 수 있습니다.

## 오류·권한

- 401: 교사 인증 또는 학생 참가자 토큰 누락/불일치
- 404: 다른 교사의 평가·다른 평가의 학생·존재하지 않는 리포트 또는 버전. 리포트 미생성은 `REPORT_NOT_FOUND`
- 400: version이0 이하, 정수가 아님, 잘못된 boolean 등 요청 형식 오류
- 500: 문서 생성 실패(기존 JSON 오류 형식). 실패 시 HWP 첨부를 성공 응답으로 보내지 않습니다.

기존 `ReportService`의 교사 평가 접근·학생 본인 인증을 그대로 사용합니다. 학생에게는 본인 리포트만 제공합니다. 데이터는 서버 메모리에서 문서로 변환하며 외부 변환 서버·한글 프로그램·LibreOffice 설치 또는 별도 라이선스 키가 필요하지 않습니다.

## 라이브러리·검증

`kr.dogfoot:hwplib:1.1.11`을 버전 고정하여 사용합니다. 라이브러리는 Apache-2.0이며, HWP 생성에는 한컴 공개 HWP5 명세를 참고한 구현을 사용합니다. [hwplib 원문](https://github.com/neolord0/hwplib)

본 제품은 한글과컴퓨터의 HWP 문서 파일(.hwp) 공개 문서를 참고하여 개발하였습니다.

자동 검증은 제목 글자 크기·굵기·중앙 정렬, 실제 정보 표·6행 점수표·반복 머리글과 기존 OLE 시그니처·HWP5 헤더·라이브러리 재읽기·한글 텍스트 추출, 다문항·빈/긴 답안, 표 텍스트, 교사 검토, 버전 고정, 원문 기본 제외/선택 포함, 접근 권한을 검사합니다. 독립 HWP5 파서로도 생성 샘플의 본문 추출을 확인했습니다. 실제 한글 데스크톱 앱의 화면 배치는 아직 검증하지 않았으며 별도 확인이 필요합니다.


제출 기록이 있는 학생은 leave 후에도 기존 토큰으로 본인 HWP를 다운로드할 수 있습니다. active를 재활성화하거나 답안 수정 권한을 복구하지 않습니다. 미생성 리포트는404 REPORT_NOT_FOUND이며 POST reports가 선행되어야 합니다.
