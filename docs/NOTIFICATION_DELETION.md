# 알림 삭제 API

두 API 모두 교사 `Authorization: Bearer {accessToken}` 인증이 필요합니다. 사용자 ID는 요청에서 받지 않으며 현재 교사의 알림만 삭제합니다.

| 메서드 | 경로 | 요청 본문 | 성공 |
|---|---|---|---|
| DELETE | `/api/notifications/{id}` | 없음 | 200 `{ "deleted": 1, "unreadCount": 2 }` |
| DELETE | `/api/notifications` | 없음 | 200 `{ "deleted": 3, "unreadCount": 0 }` |

- `deleted`: 이번 요청으로 실제 삭제 처리한 개수. 읽은 알림·안 읽은 알림을 모두 삭제할 수 있습니다.
- `unreadCount`: 삭제 처리 뒤 조회한 본인의 현재 접근 가능한 안 읽은 알림 수. 새 알림은 이후 별도로 생성될 수 있습니다.
- 개별 삭제의 없는·타인·이미 삭제한 알림은 같은 404 `NOTIFICATION_NOT_FOUND`입니다. 공유 해제로 더 이상 조회할 수 없는 알림도404입니다.
- 전체 삭제는 현재 조회 가능한 본인 알림만 대상으로 합니다. 다른 교사나 공유 해제로 숨겨진 알림은 삭제하지 않습니다. 비어 있거나 재요청하면200·deleted=0입니다.
- 로그인 누락·만료는401입니다. 비정수 ID 등 형식 오류는400입니다.

## 삭제 후 동작

`notifications.deleted_at`에 서버 UTC 시각을 저장합니다. 목록의 items·totalElements·totalPages, 미읽음 개수, 개별·전체 읽음 처리는 삭제한 알림을 제외합니다. 삭제가 이벤트의 원본 학생 답안·학습 기록·제출·채점 결과를 변경하지 않습니다.

알림 행과 `dedupe_key`는 중복 방지를 위해 내부에 보존합니다. 같은 이벤트가 재시도되더라도 삭제한 알림을 다시 생성하지 않습니다. 서로 다른 새 이벤트의 알림은 계속 생성됩니다. 이 API는 사용자 알림함에서의 삭제이며 원본 행의 물리 삭제·보존 이력 조회·복구 API를 제공하지 않습니다. 기존 평가·계정 삭제 작업에서는 관련 알림 행도 기존대로 삭제합니다.

개별 읽음은 행 잠금으로 삭제와 직렬화하고, 삭제는 본인·가시성·미삭제 조건을 포함한 원자적 UPDATE로 처리합니다. 기존 DB는 `ADD COLUMN IF NOT EXISTS`로 컬럼을 추가하며 기존 알림을 삭제하지 않습니다.

프런트에서는 성공 후 목록을 다시 조회하고 응답의 unreadCount로 표시를 갱신할 수 있습니다. 이번 작업은 백엔드만 변경합니다.
